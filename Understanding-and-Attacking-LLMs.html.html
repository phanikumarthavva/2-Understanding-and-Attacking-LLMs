SECTION 01

Introduction to Large Language Models

Before you can attack or defend an LLM, you need an accurate mechanical picture of what it is: a probabilistic next-token predictor, trained at scale, wrapped in an application. Almost every attack in this document exploits one of those three layers.

1.1  Definition

A Large Language Model (LLM) is a neural network — in practice, a Transformer — trained on very large text corpora to model the probability distribution of the next unit of text (a token) given the text that came before it. "Large" refers to two dimensions that scale together: the number of learned parameters (billions to trillions) and the size of the training corpus (hundreds of billions to trillions of tokens).

Two properties matter for security:

  • It is generative and probabilistic. The model does not retrieve a stored answer; it samples a plausible continuation. The same input can yield different outputs, and confidently-worded output can be entirely fabricated (a hallucination). Attackers weaponise both — hallucinations become squattable package names, and non-determinism frustrates naive signature detection.
  • It cannot separate instructions from data. A classic program has a control plane (code) and a data plane (input) that are architecturally distinct. An LLM receives a single undifferentiated stream of tokens. System prompt, developer instructions, user input, and retrieved documents all arrive as text and are weighed by the same attention mechanism. This single fact is the root cause of prompt injection — the defining vulnerability class of the LLM era.

1.2  How LLMs work

The pipeline from raw text to generated output has a small number of stages. Understanding each one tells you where an adversary can insert themselves.

Tokenization

Text is split into tokens — sub-word units (e.g. token, ##ization) using a scheme such as Byte-Pair Encoding. Tokenization is exploitable: unusual Unicode, invisible characters, or encoding tricks (Base64, ROT13) can produce token sequences that slip past keyword-based guardrails while still meaning something to the model.

Embedding & positional encoding

Each token ID becomes a high-dimensional vector (an embedding) that captures learned meaning; positional information is added so the model knows token order. Semantically similar tokens sit close together in this space — the property that makes embedding-based retrieval (and RAG) possible, and that also lets an attacker craft inputs that are "near" a target concept.

The Transformer block & self-attention

The core innovation (Vaswani et al., 2017, "Attention Is All You Need") is self-attention: for every token, the model computes how much every other token should influence it, in parallel. Stacking many attention + feed-forward blocks lets the model build a rich contextual representation. Because attention weighs all tokens in the context window against each other, an injected instruction buried in a retrieved document can pull the model's behaviour just as strongly as the developer's system prompt.

Output distribution & sampling

The final layer emits a probability (via softmax) over the whole vocabulary for the next token. A decoding strategy then picks one — greedily, or by sampling controlled by temperature and top-p. Higher temperature means more randomness. This stage is why identical prompts give varying answers, and why "just block the bad output string" is not a durable control.

SECURITY READ-THROUGH

Map the stages to attack surface: tokenizer → obfuscation/encoding bypass; context window → prompt injection & instruction/data confusion; training data → poisoning & backdoors; output layer → data leakage, insecure rendering, unsafe tool calls. Every later section returns to these four.

1.3  Importance & impact

LLMs matter to security not because they are novel, but because of where they are being placed: as reasoning layers wired directly into email, code repositories, ticketing systems, customer support, SOC tooling, and — most consequentially — autonomous agents that can call tools, browse, and execute actions on a user's behalf.

  • New attack surface, old consequences. A prompt injection is novel; the outcome — arbitrary code execution, data exfiltration, fraudulent transactions — is not. The LLM becomes a confused deputy: a trusted component that an attacker persuades to misuse its own privileges.
  • Trust inversion. Organisations grant agents broad access on the assumption the model is loyal. Once the model can be steered by untrusted input (a web page, an email, a calendar invite), that access becomes the attacker's access.
  • Scale for the offence too. The same generative capability that helps defenders writes fluent phishing at volume, generates polymorphic malware, and — as of 2026 — drives semi-autonomous intrusion campaigns. Section 6 covers the criminal tooling built around exactly this.

This is why frameworks like MITRE ATLAS exist: to give this new-but-familiar threat landscape a shared vocabulary, which Section 5 works through tactic by tactic.

SECTION 02

Understanding LLMs: Two Architectures

"Transformer" is one idea with two dominant families. Knowing which family a system uses tells you what it can be made to do — and therefore how you would attack it.

2.1  GPT — Generative Pre-trained Transformer

GPT is a decoder-only, autoregressive architecture. It is trained with a single objective — predict the next token — over enormous unlabelled corpora, then adapted to follow instructions (Section 3). "Causal" (or masked) self-attention means each position can attend only to earlier positions, which is what makes coherent left-to-right generation possible.

  • Pre-trained — general language competence learned once, at great cost, from raw text.
  • Generative — produces novel text, code, and structured output rather than labelling existing text.
  • Transformer — the attention-based backbone from Section 1.

GPT-family models (and their open counterparts — LLaMA, Mistral, Falcon, GPT-J, and so on) are what people mean by "an LLM" in the chat/agent sense. They are the target of prompt injection, jailbreaks, system-prompt extraction, and tool-abuse — the generative-AI-specific techniques that dominate Section 5. Notably, GPT-J 6B, an open model released by EleutherAI in 2021, is the base that the original WormGPT was built on (Section 6).

2.2  BERT — Bidirectional Encoder Representations from Transformers

BERT (Google, 2018) is an encoder-only architecture built for understanding rather than generation. Its key training objective is the Masked Language Model: random tokens are hidden and the model predicts them using context from both directions. This bidirectional context yields rich representations well-suited to classification, named-entity recognition, sentiment analysis, and — relevant to security — powering the embedding and retrieval components inside larger systems.

BERT is less a chatbot and more a workhorse for text understanding embedded in pipelines. In an attack context it appears on both sides: as a defensive classifier (e.g. an ML phishing/malware detector an attacker wants to evade), and as a component an attacker may try to poison or fingerprint.

WHY THE DISTINCTION MATTERS FOR ATTACKERS

A generative (GPT-style) target invites input-side manipulation — you steer what it produces and what tools it invokes. A discriminative (BERT-style) target invites evasion and poisoning — you manipulate inputs to flip a classification, or corrupt training data to plant a backdoor. ATLAS reflects this split explicitly through its Predictive AI vs Generative AI vs Agentic AI platform tags on each technique.

SECTION 03

Training & Augmenting LLMs

A model's capabilities are shaped in three ways: what it learns during pre-training, how it is fine-tuned afterward, and what external knowledge is fed to it at run time. Each is a distinct point of attack.

3.1  Foundational vs fine-tuned models

A foundation (base) model is the product of expensive, general-purpose pre-training on a broad corpus. It has broad competence but is not yet aligned to a task or to human preferences — a raw base model will happily complete text without regard for helpfulness or safety.

A fine-tuned model takes that foundation and continues training on a narrower, curated dataset to specialise it. Two important sub-types:

  • Supervised fine-tuning (SFT) / instruction tuning — teaches the model to follow instructions and adopt a helpful assistant format.
  • Alignment tuning (RLHF / preference optimisation) — shapes the model toward human-preferred, safer responses. Guardrails and refusals largely live here. Jailbreaks (ATLAS AML.T0054) are attempts to override precisely this layer.

ATTACK SURFACE ACROSS THE LIFECYCLE

  • Training-time: data poisoning (AML.T0020), model backdoors / trojans, and publishing poisoned datasets or models to the supply chain (AML.T0115). A poisoned base model contaminates every downstream fine-tune.
  • Artifact-time: a distributed model file can carry malware in an unsafe serialization format, or be corrupted to defeat a scanner while still executing (AML.T0076). Real cases include malicious models on Hugging Face and the compromised PyTorch dependency chain.
  • Inference-time: jailbreaks and prompt injection attack the aligned behaviour directly, without touching weights.

3.2  Retrieval-Augmented Generation (RAG)

A fine-tuned model still only knows what was in its training data, frozen at a cutoff. RAG closes that gap by fetching relevant external documents at query time and inserting them into the prompt as context, so the model can answer using current or private knowledge it never memorised.

The flow: the user query is embedded into a vector; a vector database returns the nearest-matching document chunks; those chunks are concatenated with the query and the system prompt; the assembled prompt goes to the LLM; the LLM answers grounded in the retrieved text.

WHY RAG IS A SECURITY PIVOT

RAG dissolves the boundary between "the model's knowledge" and "attacker-supplied text." Anything an adversary can plant where the RAG system indexes — a wiki page, a shared drive, a public web page, an email — can surface as retrieved context and carry hidden instructions (indirect prompt injection) or false facts. This is why ATLAS has an entire cluster of RAG-specific techniques, and why the Morris II self-replicating worm and Slack AI / M365 Copilot exfiltration cases all pivot through retrieval. Treat every indexed source as untrusted input.

SECTION 04

Use Cases of LLMs

The point of cataloguing use cases here is not the capabilities themselves but the trust and access each one is granted. Where an LLM is wired, and what it is allowed to touch, defines the blast radius when it is subverted.

4.1  Text Generation

The canonical capability: producing fluent novel text — drafting, summarising, translating, code generation, and content creation. Generation is what makes LLMs productive and what makes them dangerous in adversarial hands.

OFFENSIVE MISUSE

Fluent generation at scale powers phishing and business-email-compromise lures (AML.T0052.000 — Spearphishing via Social Engineering LLM), malware and exploit code (AML.T0102 — Generate Malicious Commands), disinformation, and deepfake text/media (AML.T0088). The criminal tools in Section 6 exist almost entirely to remove the guardrails that would otherwise refuse these requests.

4.2  Text Understanding

Classification, extraction, sentiment, semantic search, and content moderation — the discriminative tasks BERT-style models excel at. This is heavily used defensively: ML-based malware detectors, phishing-page classifiers, and spam filters are themselves models.

OFFENSIVE MISUSE

When the "understanding" model is a defence, the attacker's goal is evasion (AML.T0015 — Evade AI Model) or poisoning its training data. ATLAS case studies include evading a deep-learning malware C2 detector, bypassing Cylance's AI malware detection, ProofPoint evasion, and attempted evasion of an ML phishing-webpage detector. When the understanding model is the attacker's own reconnaissance tool, it triages stolen data or fingerprints targets at scale.

4.3  Conversational AI & Agents

Multi-turn assistants that maintain context — and, increasingly, agents that plan and act: calling tools, querying databases, running code, browsing the web, sending email, and operating other software (including via the Model Context Protocol, MCP). This is the highest-risk deployment pattern because the model's decisions become actions in the world.

THE CONFUSED-DEPUTY PROBLEM, MADE CONCRETE

An agent inherits the privileges of the identity it runs as. If untrusted content can steer it (indirect injection, poisoned RAG, a crafted email or calendar invite), the attacker inherits those privileges without ever authenticating. ATLAS's newest tactics and mitigations — AI Agent Authority Expansion Controls (AML.M0037), Human In-the-Loop for AI Agent Actions (AML.M0029), Restrict AI Agent Tool Invocation on Untrusted Data (AML.M0030) — exist specifically to bound this. Section 5's agentic techniques (tool poisoning, tool invocation, data destruction via tools) all live in this loop.

SECTION 05

Attack Tactics & Techniques

A tactic is an adversary's goal ("why"); a technique is how they achieve it. MITRE organises both into a matrix so defenders can reason about coverage. There are two matrices you must not confuse.

5.1  MITRE ATT&CK

MITRE ATT&CK (Adversarial Tactics, Techniques & Common Knowledge) is the globally-used knowledge base of adversary behaviour against conventional IT — endpoints, networks, cloud, ICS. Tactics are ordered roughly by attack progression, from Reconnaissance through Impact. Every technique carries an ID like T1566 (Phishing).

ATT&CK is a living framework. Its most significant structural change in years shipped as ATT&CK v19 on 28 April 2026: the long-overloaded Defense Evasion tactic (TA0005) was split into Stealth (which keeps TA0005 — blending into legitimate behaviour) and Defense Impairment (TA0112 — actively disabling controls). Enterprise ATT&CK v19 comprises 15 tactics, 222 techniques, and 475 sub-techniques. If your detections still map to the old unitary "Defense Evasion," they now describe a narrower world and need remapping.

5.2  MITRE ATLAS matrix

ATLAS (Adversarial Threat Landscape for Artificial-Intelligence Systems) is ATT&CK's counterpart for AI. It reuses ATT&CK's Tactic → Technique → Mitigation → Case-study structure but focuses on attacks against AI-enabled systems, abuse of AI capabilities, and harmful autonomous behaviour. IDs use the AML. prefix — tactics AML.TA####, techniques AML.T####, mitigations AML.M####, case studies AML.CS####.

Most ATLAS tactics are inherited from ATT&CK; two are AI-native — AI Model Access and AI Attack Staging (renamed AI Attack Adaptation in the 2026.08 release, reflecting agents that adapt an attack at runtime). The framework has grown rapidly with agentic-AI threats: the release used as the baseline throughout this section, ATLAS v2026.09 (15 September 2026), contains 16 tactics, 208 techniques, 40 mitigations and 73 case studies — of which 23 are documented real-world incidents rather than red-team exercises.

SECTION 06

Real-World LLM Attack Tools

In mid-2023, a wave of “dark GPTs” appeared on underground forums and Telegram — LLMs stripped of guardrails and sold to criminals. They are the practical embodiment of Section 4’s offensive misuse. Treat vendor claims with scepticism: several were credible, uncensored models; others were likely jailbroken-prompt wrappers or outright scams. What follows is drawn from the original threat-intel reporting.

HOW TO READ THESE

All three are “uncensored assistant” products: the selling point is the removal of the alignment layer (Section 3.1) so the model will write phishing, malware, and fraud content on demand. In ATLAS terms they are AML.T0016.002 (Obtain Capabilities: Generative AI) sold as-a-service, used to drive AML.T0052 phishing, AML.T0102 malicious-command generation, and BEC fraud. Their real significance is lowering the skill floor for cybercrime.

6.1  WormGPT

The archetype. First announced as in-development on Hack Forums in March 2023 by a threat actor using the alias “Last”, and publicly released around June 2023, marketed as “the biggest enemy of ChatGPT” and a blackhat alternative. Security firm SlashNext analysed it in July 2023.

  • Base model: reportedly GPT-J 6B — the open-source 6-billion-parameter model released by EleutherAI in 2021 — fine-tuned by the creator on malware code, exploit write-ups, and phishing material.
  • Primary use: business-email-compromise (BEC) and phishing. SlashNext had it generate a BEC lure and described the result as remarkably persuasive.
  • Pricing: reported around €60–€100/month or €550/year, with a private setup around €5,000.
  • Shutdown: the original was shut down on 8 August 2023 after investigative journalist Brian Krebs identified the operator, drawing intense media attention.
  • Afterlife: “WormGPT” became a brand. Researchers at Cato Networks (2025) uncovered new variants that were in fact jailbroken wrappers around commercial models (xAI’s Grok and Mistral’s Mixtral), and a later “WormGPT 4” was advertised with tiered pricing.

6.2  FraudGPT

Surfaced within days of WormGPT, advertised on the dark web and Telegram from around 22–25 July 2023 by an actor using the handle “CanadianKingpin12” (a known carding/fraud vendor). Documented by Netenrich and SlashNext.

  • Positioning: an all-in-one offensive toolkit “with no boundaries.” Advertised capabilities: writing spear-phishing and BEC emails, creating undetectable malware, generating phishing/scam pages, finding vulnerabilities and leaks, carding, and hacking tutorials. The seller claimed the model was refreshed every one to two weeks and swapped between underlying models.
  • Pricing: subscription — roughly $200/month, ~$1,000 for six months, up to $1,700/year; the seller claimed 3,000+ sales.
  • Distribution shift: the actor moved promotion to Telegram after clear-net forum threads were removed, and later teased related tools (“DarkBERT”, “DarkBARD”). Promotional channels and posts later disappeared.

6.3  XXXGPT

Announced on the XSS.is forum around late July 2023 (dark-web monitor Falcon Feeds flagged it on 31 July), pitched as a “revolutionary service offering personalized bot AI customization…with no censorship or restrictions,” reportedly backed by a team of five.

  • Claimed focus: malicious code rather than just email — botnets, remote-access trojans (RATs), keyloggers, infostealers, ATM-malware kits, and cryptostealers.
  • Pricing: reported around $90 for a one-month license.
  • Credibility: heavily disputed. Trend Micro noted there was essentially no follow-up posting, no user feedback, and no testimonials; Sophos found a tester unable to get the demo to produce malware and observed censored responses — consistent with a possible jailbroken-prompt wrapper or a scam. Its current status is unclear. A useful reminder that underground “capability” claims are marketing until verified.

DEFENDER TAKEAWAY

You cannot block these tools at the source, and their output is designed to look legitimate. Defence shifts left and right of the model: reduce believable pretext (limit public info, brand-impersonation monitoring), harden the human layer against better phishing (out-of-band verification for payments, ATLAS AML.M0018 user training), and detect on behaviour, not content — the malware and fraud still have to touch your endpoints, identity, and payment rails, where conventional ATT&CK-aligned detection and controls still apply.
